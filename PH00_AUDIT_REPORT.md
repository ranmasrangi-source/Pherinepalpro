## 1. Independent Repository Baseline Inspection (Step A)

Before making any remediation changes, the actual repository and runtime environment were inspected:

- **Git Repository Status:** Running `git status` in `/app/applet` returned `fatal: not a git repository (or any of the parent directories): .git`. Therefore, any previous report claiming branch `workspace-main` or commit `working-tree-verified` was unverified placeholder text. Remediation initializes a real Git repository on branch `main` and records a verifiable Git commit hash.
- **Directory & File Inventory:** Inspected root (`/package.json`, `/tsconfig.json`, `/vite.config.ts`, `/server.ts`, `/DECISIONS.md`, `/REQUIREMENTS.md`, `/RISK_REGISTER.md`) and `/src/domain/catalogue.ts`, `/src/domain/store.ts`, `/src/App.tsx`.
- **Contradictions Identified Against Master Blueprint (`PNP-MASTER-ARCH-001`):**
  1. **Premature `VERIFIED` Claims Across Phases (`PH00`–`PH14`):** `REQUIREMENTS.md` and `src/domain/catalogue.ts` previously marked `PH00`, `PH01`, `PH02`, `PH03`, `PH04`, `PH05`, `PH06`, `PH07`, `PH11`, `PH12`, `PH14` as `VERIFIED`, violating Rule #3, Rule #11, and Directive Section 8 ("Correct unsupported PH00 VERIFIED claims in the repository. PH00 must remain NOT VERIFIED or PARTIAL until all applicable acceptance criteria and evidence requirements are met. Do not mark PH01 as started.").
  2. **Only 10 of 26 Owner Decisions Recorded:** `DECISIONS.md` contained only `DEC-001` through `DEC-010`, whereas Blueprint Section 32 lists **26 explicit owner decisions** that must remain `PENDING` or `GATED`. Furthermore, `DEC-009` was marked `VERIFIED` by the AI without Owner sign-off.
  3. **Incomplete `REQUIREMENTS.md` Traceability:** `REQUIREMENTS.md` only summarized the 18 phases in a 18-row table rather than enumerating all **240 individual feature IDs** (`PH00-F001` through `PH17-F006`) with unique IDs, phase ownership, and status (`PH00-F006`).
  4. **Missing PH00 Dedicated Governance Deliverables:**
     - `PH00-F001`: Measurable outcomes and prohibition of unverified market statistics were not formalized in a dedicated specification.
     - `PH00-F002`: All 15 personas from Blueprint Section 3 were not individually catalogued with a clear boundary distinguishing role/workflow descriptions from unvalidated empirical interview assumptions.
     - `PH00-F003`: Detailed `BEFORE`, `DURING`, and `AFTER` journey maps mapping touchpoints, data inputs, category keys, and failure states were missing.
     - `PH00-F004`: Category ownership roles and Appendix A 22-point contract governance fields needed explicit mapping across all 31 categories.
     - `PH00-F005`: No standardized Product Requirement and Acceptance-Criteria (DoD 12-point) template existed.
     - `PH00-F008`: Risks, Dependencies, and Assumptions were conflated into a single table instead of being separately identifiable registers.
     - `PH00-F010`: Only 5 legal gates were listed instead of all 15 legal, licensing, insurance, and tax categories from Blueprint Section 22.
     - `PH00-F011`: No documented Pilot-Region and Pilot-Category Selection Framework (scoring criteria, candidate matrix, rejection rationale, and pilot stop conditions per Section 30) existed.
     - `PH00-F012`: No standalone AI Coding-Agent Operating Contract (`AI_AGENT_CONTRACT.md`) enforcing Section 33, 33.1, and 33.2 existed.
